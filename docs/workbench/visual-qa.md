# 工作台视觉检查

修改或审查工作台UI时，先读[当前状态与基线](status.md)。沿用已有pnpm工具链与Playwright，无新增测试框架。

## 运行

```bash
pnpm typecheck
pnpm lint
pnpm build
pnpm test:e2e
pnpm test:visual
```

`test:visual`先验证检查器能识别已知缺陷，再用独立Playwright配置启动或复用开发服务，检查四页和客户详情，共手机390×844、PC1440×900十组状态。E2E产物位于`test-results/e2e/`，视觉产物位于`test-results/visual/`；两类JSON报告均位于这两个清理目录之外。回归会在临时目录中按两种执行顺序启动真实Playwright进程，确认另一类JSON和trace文件保留。

页面运行错误、元素缺失、横向溢出、几何差异超过1px、标题等关键文字样式改变、周期文字不居中、像素差异超阈值都会返回非零退出码。整页阈值2%，局部趋势卡片、趋势绘图区、弹层、迷你图阈值3%；每像素RGB任一通道差大于24计为差异。趋势绘图区单独检查，避免卡片留白掩盖空白图表；同时按原稿主色统计实际截图中的折线像素，至少保留原稿50%的颜色像素，允许抗锯齿差异。真实绘图层隐藏的故障注入必须返回失败，不能仅依赖接近阈值的差异百分比。具体值以[机器基线](visual-baseline.json)为准。

原稿和实现会在同一浏览器、相同视口/DPR下渲染，等待字体与图表加载，减少动效、移除焦点和鼠标悬停，并把嵌套滚动位置归零。弹层尺寸回归先等待原稿动画完成再采样，覆盖普通动效和减少动效两种模式，保留1px断言。保留原稿完整截图；仅对“我的”比较参考排除已确认不交付的原型状态演示卡。周期文字依据用户确认检查居中，不要求复制原稿左对齐。

## 证据

每次采集独占`artifacts/visual-qa/runs/<UTC时间>-<随机标识>/`，保存：

- `reference-raw/`：未移除原型演示卡的原稿截图。
- `reference/`、`actual/`：同批次原稿与实现的整页及局部截图。
- `comparison/`：两栏对照及红色差异图；客户弹层与迷你图单独裁切，避免背景或留白稀释差异。
- `manifest.json`：开始/完成时间、Git HEAD、工作区是否有改动、源码文件SHA-256及组合指纹、设计基线、Node/浏览器/系统、视口、DPR、字体状态、滚动规则、测量值、像素比例及失败原因。
- `index.html`：该批次可独立查看的报告。

`latest.json`只是最近一次全量`check`批次的指针，失败也会更新并明确标记失败。局部排查与故障注入测试不更新此指针。旧批次不覆盖；历史已验收画廊保留为`accepted.html`，原有`before/`、`after/`等目录保留，采集不再写入这些历史目录。开发服务运行时打开`/artifacts/visual-qa/index.html`查看最新与历史入口。

`runs/`、`latest.json`及最新入口`index.html`由检查生成，均不提交；首次检出后执行`pnpm test:visual`即可生成最新入口。历史验收画廊`accepted.html`及其参考图单独纳入版本管理。

需要采集局部排查证据时：

```bash
# 需要已有开发服务；此批只说明局部结果，不代表全量视觉检查通过。
node scripts/visual-qa.mjs investigation sales customer
```

每次调用都会生成新目录；标签不会改变已有证据。可用`VISUAL_QA_URL`指定已启动的开发服务。`node scripts/compose-visual-qa.mjs`仅根据最新批次元数据重新生成HTML索引，不重新截图或改写参考图。

## 更新基线

设计源码hash改变时检查直接失败。先核对用户确认的新设计及取舍，再修改基线清单并在`status.md`更新当前决策、在`history.md`记录变更理由；保留旧批次。实现与原稿出现差异时，应先定位原因，避免直接放宽阈值。新增交互须扩展检查场景，尤其是挂载到页面根节点之外的弹层。

## CI

GitHub工作流`.github/workflows/checks.yml`在push、PR及手动触发时，用`.node-version`和`packageManager`指定版本安装锁定依赖，执行以上检查并上传结果和视觉批次，保留14天。视觉检查即使前面的步骤失败也会尝试执行，作业仍保留原失败状态。检查不依赖真实OAuth服务或企业微信客户端。

远端运行需要变更已提交并推送；分支保护的必需Checks由仓库设置管理。本次本地工作不包含推送、部署或更改仓库分支保护。
